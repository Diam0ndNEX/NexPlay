**8.16.9: CAUSE FOUND (owner's 8.16.8 log): every attack's `Sensors::BasicAttack.scan` went to `IOS::NullStub.method_missing` (platform_compat.rb:445; receiver Sensors::BasicAttack, `_name=:scan`, then `:each` on the nil result), so nothing was ever hit or damaged (enemies too). Why: the game loads its scripts through `FileGetter.getFileList` = `Dir[...]` then `sort_by!{ file name prefix .to_i }` (103_FileGetter.rb); Frames/Modules files (BattleSystem, Sensors, Sensors_Battle, ...) have no numeric prefix, so they all tie at 0 and keep the order `Dir[]` returned. Windows/NTFS lists alphabetically (Sensors.rb before Sensors_Battle.rb); iOS lists in arbitrary order, so Sensors_Battle.rb could load first: `class Battle_Sensor < Basic_Sensor` with Basic_Sensor missing gave the core's NullStub (const_missing) as superclass, and every Editables sensor (BasicAttack...) inherited from it. Also the HIT log now prints `BasicAttack ancestors` (should be BasicAttack < Battle_Sensor < Basic_Sensor < Object). General lesson: any game that sorts by a numeric prefix and relies on directory order can break the same way. The diagnostics (HIT/trace) stay for now. Not compiled here.**
